# Проблемы текущей архитектуры 

- Синхронный fan-out в ins-product-aggregator
Агрегатор делает запросы ко всем страховым компаниям в рамках одного цикла. При росте их числа увеличиваются задержки и вероятность ошибок

- polling каталога продуктов и тарифов
core-app и ins-comp-settlement периодически запрашивают одни и те же данные, создавая пиковую нагрузку и получая данные с разной актуальностью

- Жёсткая связность сервисов по REST
Суточный запрос ins-comp-settlement >> core-app для получения оформленных страховок делает расчёты зависимыми от доступности core-app

- Риски несогласованности данных
Локальные реплики продуктов и тарифов обновляются в разное время и могут содержать разные версии данных

# Что было сделано

- Внедрён Event Streaming (Kafka) как основной механизм обмена данными между сервисами

- Каталог продуктов и тарифов переведён на события
ins-product-aggregator публикует события об изменениях каталога
core-app и ins-comp-settlement подписываются на них и обновляют локальные реплики

- Оформленные страховки передаются через события
core-app публикует события об оформлении страховок
ins-comp-settlement потребляет их и накапливает данные для суточных расчётов без REST-запросов
